# План Code Review — Модуль авторизации банковского приложения

## Раздел 1. Цели ревью
* Обеспечение максимальной безопасности модуля авторизации.
* Проверка соответствия обработки персональных данных закону 152-ФЗ.
* Исключение утечек логинов, паролей и сессионных токенов.

## Раздел 2. Критерии оценки кода
* Отсутствие открытого логирования конфиденциальных данных.
* Корректная инвалидация токенов при выходе (logout).
* Покрытие кода юнит-тестами для проверки двухфакторной аутентификации (2FA).

## Раздел 8. Разрешение споров и эскалация

### 1. Правило "Двух голосов" (Состав команды ревью: Канышев Д. А., Гущин Т. А., Гришин Р. Л.)
Поскольку наша экспертная команда ревью состоит из 3 человек, при возникновении архитектурных разногласий по коду разработчика Иванова финальное решение принимается путем **голосования большинства**. 
* Если Канышев Д. А. требует переписать функцию авторизации, а Гущин Т. А. считает её безопасной, секретарь команды Гришин Р. Л. фиксирует аргументы сторон и организует финальное голосование. 
* Разработчик Иванов обязан безоговорочно подчиниться решению большинства членов комиссии (2 голоса против 1).

### 2. Эскалация (Критические уязвимости безопасности)
Если спор касается потенциальной критической уязвимости безопасности (обработка персональных данных по 152-ФЗ, хранение паролей или токенов сессий), а разработчик Иванов не согласен с замечаниями экспертов (Канышева, Гущина, Гришина), обсуждение внутри команды прекращается. 
* Вопрос незамедлительно эскалируется на уровень **CISO (Директора по информационной безопасности)** или **Главного архитектора банка**. 
* Код модуля авторизации не может быть слит в ветку `develop` без официального письменного апрува от ИБ-департамента.

### 3. Время на дискуссию
На обсуждение одного спорного комментария в Pull Request внутри экспертной группы выделяется **не более 2 часов** в асинхронном режиме. Если по истечении этого времени консенсус между Канышевым, Гущиным и Гришиным не достигнут, авторы спора обязаны созвониться на **15-минутный синхронный звонок**. Если и после звонка решение не принято, ветка спора немедленно эскалируется на уровень выше.
