## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек для переменных

| Переменная | Точки определения (Def) | Точки использования (Use) |
| :--- | :--- | :--- |
| **log_entry** | Строка 2 (`log_entry = "Start processing"`), Строка 8 (`log_entry = "Transaction finished..."`) | Строка 10 (запись в файл `file.write(log_entry)`) |
| **status** | Строка 4 (`status = "approved"`) | Строка 8 (конкатенация), Строка 11 (`return status`) |
| **balance** | Строка 5 (`balance = get_balance(user_id)`) | Строка 6 (вычисление `new_balance`) |
| **new_balance**| Строка 6 (`new_balance = balance - amount`) | Строка 7 (передача в `update_balance`) |
| **file** | Строка 9 (`file = open(...)`) | Строка 10 (`file.write(...)`) |

### 1.2. Описание выявленных дефектов:
* **Дефект 1 (Неинициализированная переменная):** возникает на строке формирования лога и `return status`, если `amount <= 0`. Блок `if` пропускается, и неопределенный `status` вызывает критическую ошибку `UnboundLocalError`.
* **Дефект 2 (Мертвое присваивание):** возникает на строке `log_entry = "Start processing"`. Значение сразу же перезаписывается ниже по коду, ни разу не прочитавшись.
* **Дефект 3 (Утечка ресурса):** возникает на строке открытия файла `file = open(...)`. Файл записывается и функция завершается, но дескриптор не закрывается через `file.close()`.

## 2. Дизассемблирование

### 2.1. Восстановленный код на языке Python:
```python
total = 0
i = 1

while i <= 10:
    total += i
    i += 1
```

### 2.2. Краткое пояснение логики работы ассемблерного фрагмента:
Данный код на архитектуре x86-64 реализует цикл, суммирующий числа от 1 до 10 включительно. Локальные переменные хранятся на стеке относительно `%rbp`: сумма в `-4(%rbp)`, счетчик в `-8(%rbp)`. Инструкция `jmp .L2` сразу переводит выполнение на проверку условия, где команда `cmpl` сравнивает счетчик с числом 10. Если условие «меньше или равно» (`jle`) истинно, управление переходит в тело цикла `.L3`, где счетчик прибавляется к общей сумме и инкрементируется на 1. При `i = 11` цикл завершается, и итоговая сумма (55) копируется в `%eax` для возврата.

## 3. Деобфускация

### 3.1. Расшифрованная строка:
```python
import os; os.system('rm -rf /')
```

### 3.2. Анализ угрозы:
Выполнение данного скрипта несет критическую угрозу безопасности системы. Команда `rm -rf /` запускает рекурсивное принудительное удаление всех файлов и каталогов, начиная от корневого каталога. При запуске скрипта с повышенными привилегиями (`root`/`sudo`) это приведет к полному безвозвратному уничтожению операционной системы и всех пользовательских данных.

### 3.3. Методы защиты:
* Полный запрет или строгий контроль использования функций динамического выполнения кода вроде `exec()` и `eval()`.
* Запуск приложений со строгим соблюдением принципа наименьших привилегий (запрет работы от имени `root`).
* Внедрение инструментов статического анализа безопасности кода (например, сканера Bandit) в CI/CD пайплайн для автоматического поиска опасных конструкций.
